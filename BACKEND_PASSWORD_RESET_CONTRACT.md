# Password Reset — Frontend / Backend Contract (Masahati)

This document is the exact contract the **Laravel backend team** must implement so the
forgot-password flow matches the frontend. The frontend is DONE and needs no changes.

## Current bug (what caused `test.md`)

The reset email's link points directly at the API:

```
https://back-end-kwba.onrender.com/api/reset-password?token=...&email=...
```

Browsers open that with **GET**, but that route is **POST-only**, so Laravel throws
`MethodNotAllowedHttpException` ("The GET method is not supported for route
api/reset-password. Supported methods: POST."). That is the error on the desktop.

**Root cause:** the emailed link must land on the **frontend**, not on the API.

---

## Backend must implement 3 things

### 1) `POST /api/forgot-password`  (already works — returns 200)

- **Request body:**
  ```json
  { "email": "user@example.com" }
  ```
- **Success:** `200` `{ "message": "..." }` — ALWAYS return 200/success whether or not the
  email exists (do NOT reveal whether an account registered — prevents user enumeration).
- **Validation:** if `email` is malformed (`422`):
  ```json
  { "errors": { "email": ["The selected email is invalid."] } }
  ```
  (Frontend checks `status === 422 && err.data.errors.email` and translates.)
- **Rate limit / throttle:** return `429`/too-many-requests; frontend translates to
  "طلبات كثيرة جداً".

### 2) Reset email must point to the FRONTEND, not `/api/reset-password`

The link generated by the backend's password-reset notification must be:

```
{FRONTEND_URL}/reset-password?token={TOKEN}&email={EMAIL}
```

- `{FRONTEND_URL}` = the deployed frontend host (Netlify/Vercel/etc.), NOT the backend.
- `{EMAIL}` must be **URL-encoded** (use `urlencode()`).
- `{TOKEN}` = the broker token from `Password::broker()->createToken($user)`.

Laravel defaults to `config('app.url')`. Fix either:

- **(a) Simplest:** set `APP_URL` env var on Render to the frontend host, **OR**
- **(b) Recommended (custom notification):** create `app/Notifications/ResetPassword.php`
  extending `Illuminate\Auth\Notifications\ResetPassword` and override `toMail()` to build
  `url('/reset-password') . '?token=...&email=' . urlencode(...)`, then register it in
  `AppServiceProvider::boot()` via `Password::broker()->toMailUsing(...)`, and ensure
  `APP_URL` = frontend host.

The frontend already handles this link: it reads `token` and `email` from the URL
(`ResetPasswordPage.jsx`), and if `email` is missing it lets the user type it.

### 3) `POST /api/reset-password`  (frontend calls this; GET must stay unused by links)

- **Request body:**
  ```json
  {
    "email": "user@example.com",
    "token": "....",
    "password": "newpass123",
    "password_confirmation": "newpass123"
  }
  ```
- **Success:** `200`/`302` with a JSON body (frontend reads body; on success it navigates
  to `/login`).
- **Validation / errors (`422`):** return under the correct field keys so the frontend maps
  them:
  ```json
  { "errors": { "password": ["..."], "token": ["..."], "email": ["..."] } }
  ```
  - `password` — e.g. min 8 chars ("كلمة المرور يجب ألا تقل عن 8 أحرف.")
  - `token` — invalid/expired token ("رابط إعادة التعيين غير صالح أو منتهٍ.")
  - `email` — invalid email.
- **Invalid/expired token:** return `422` with `errors.token`.
- **Do NOT** expose `GET /api/reset-password`.
- Frontend also handles **`405` Method Not Allowed** gracefully (shows a friendly message),
  so even if a browser hits the API directly, users see a clear Arabic error instead of a
  raw stack trace — but the real fix is making the email link point to the frontend.

## Message / status mapping (frontend expectations)

| Backend | Frontend shows |
|---|---|
| `200` forgot-password | "تم إرسال الرابط" success screen |
| `422` forgot (email.errors[0]) = "The selected email is invalid." | "هذا البريد غير مسجّل لدينا أو غير صحيح." |
| `429` / throttle | "طلبات كثيرة جداً. انتظر قليلاً وحاول مجدداً." |
| `200` reset-password | "تم تغيير كلمة المرور" → redirect to `/login` |
| `422` reset → errors.password (short) | "كلمة المرور يجب ألا تقل عن 8 أحرف." |
| `422` reset → errors.token | "رابط إعادة التعيين غير صالح أو منتهٍ." |
| `405` (GET on reset, fallback) | "رابط إعادة التعيين مفتوح بطريقة غير صحيحة…" |

---

## Acceptance criteria (how the backend team verifies)

1. Request `POST /api/forgot-password` with a registered email → gets the **frontend** URL
   in the email: `{FRONTEND}/reset-password?token=...&email=...`.
2. Clicking that link opens the React app (NOT a raw `/api/...` response).
3. Submitting the reset form POSTs `{email, token, password, password_confirmation}` to
   `/api/reset-password` and returns success.
4. Login with the new password works.
